# XRay.PsdFx 项目说明

> 目标框架：**.NET Framework 4.5**（C# 7.3） · 零第三方依赖 · 纯托管
> 一句话：**读取 PSD/PSB 文件里的图层效果（图层样式）全部属性，不解码像素。**

---

## 1. 它能做什么

| 能 | 不能 |
|---|---|
| 读文件头：尺寸、通道、位深、颜色模式、PSD/PSB | 解码像素（图层通道、合并图像） |
| 读图层：名称（Unicode）、可见性、混合模式、不透明度 | 渲染/合成图像 |
| 读**全部 10 种图层效果**及其**全部文件属性** | ICC 颜色管理（灰/CMYK 用内置公式） |
| 读等高线曲线、渐变（色标/透明标/噪点）、图案摆放 | 解码图案瓦片像素（在全局 `Patt` 块里） |
| 保留每个效果的原始 `Descriptor` 与原始 tagged block 字节 | 渐变逐像素求值 |

支持的十种效果：投影、内阴影、外发光、内发光、斜面浮雕、光泽、颜色叠加、
渐变叠加、图案叠加、描边；另外兼容 Photoshop 5 的老 `lrFX` 格式。

## 2. 三十秒上手

### 引入项目（三选一）

**A. 源码复制（最简单）**：把 `src/XRay.PsdFx/` 下 13 个 `.cs` 文件拷进你的项目。
没有 NuGet 依赖，老式 .csproj 只需 `<Compile Include="XRay.PsdFx\*.cs" />`。

**B. 引用 DLL**：

```powershell
dotnet build XRay.PsdFx/src/XRay.PsdFx -c Release
# 产物：src/XRay.PsdFx/bin/Release/net45/XRay.PsdFx.dll
```

**C. 同解决方案**：`ProjectReference` 指向 `XRay.PsdFx.csproj`。

### 五行代码

```csharp
using XRay.PsdFx;

var doc = PsdDocument.FromFile(@"C:\test\sample.psd");
foreach (var layer in doc.Layers)
    foreach (var fx in layer.Style?.ActiveEffects ?? new PsdEffect[0])
        Console.WriteLine($"{layer.Name} / {fx.Kind} / 杂色={fx.Noise}");
```

### 输出长这样（真实 Photoshop 文件）

```
图层 1 / DropShadow / 杂色=0.1
图层 1 / OuterGlow / 杂色=0.28
图层 1 / BevelEmboss / 杂色=
```

`杂色=` 后面为空，表示**文件里没有 `Nose` 键**；`0` 表示**有键但为零**——
两者含义不同，这是 `float?` 而不是 `float` 的原因。

## 3. 项目结构

| 文件 | 职责 | 大约行数 |
|---|---|---|
| `PsdDocument.cs` | 文档模型 + 入口 `FromFile` / `FromBytes` | 120 |
| `PsdParser.cs` | 文件结构：头、颜色模式、图像资源、图层记录、tagged block | 420 |
| `PsdLayer.cs` | 图层模型（名称、可见性、混合模式、原始块） | 90 |
| `Descriptor.cs` | Action Manager 描述符（`Objc`）解析与取值 | 520 |
| `Effects.cs` | **核心**：描述符 → `PsdEffect` 全部属性 | 660 |
| `Contour.cs` | 等高线曲线 `ShpC` | 130 |
| `Gradient.cs` | 渐变文件属性（含噪点渐变） | 330 |
| `Pattern.cs` | 图案摆放 | 70 |
| `LegacyEffects.cs` | PS5 `lrFX` → 描述符形状 | 260 |
| `BigEndianReader.cs` | 带边界检查的大端读取器 | 200 |
| `BlendModes.cs` / `PsdColor.cs` / `PsdFormatException.cs` | 枚举、颜色、异常 | 260 |

调用关系只有一条线：

```
FromFile → PsdParser.Parse
             ├─ ReadHeader            文件头
             ├─ ReadColorModeData     颜色模式数据（跳过）
             ├─ ReadImageResources    图像资源（只取 1037/1049 全局光）
             ├─ ReadLayerAndMaskInfo  图层与蒙版区
             │    └─ ReadLayerRecord × N
             │         └─ ReadTaggedBlocks → ApplyTaggedBlocks
             │                               ├─ luni → 图层名
             │                               └─ lfx2 → Descriptor → PsdLayerStyle.Parse
             └─ （到此为止，不读图像数据）
```

## 4. 数据是怎么流动的（核心只有 4 步）

**① 找到效果块** `PsdParser.cs` → `ApplyTaggedBlocks`

```csharp
var data = new byte[block.Data.Length - 4];       // 跳过 4 字节对象版本
Array.Copy(block.Data, 4, data, 0, data.Length);
var parsed = Descriptor.ReadVersioned(new BigEndianReader(data));  // key/value 树
```

**② 认出效果种类** `Effects.cs` → `PsdLayerStyle.Parse`

```csharp
foreach (var item in root.Items)      // "DrSh" / "OrGl" / "ebbl" ...
{
    var kind = KindOf(item.Key);      // → PsdEffectKind.DropShadow
    effects.Add(Project(kind.Value, descriptor.GetBoolean("enab"), descriptor, ...));
}
```

**③ 一个 switch 把字段填进对象** `Effects.cs` → `Project()`

```csharp
case PsdEffectKind.DropShadow:
    effect.BlendMode = Mode(d, "mul ");                    // Md   → 枚举
    effect.Color     = d.GetColor("Clr ");                 // Clr  → PsdColor
    effect.Opacity   = Percent(d, "Opct", 75);             // 75 #Prc → 0.75
    effect.Angle     = Angle(d, globalAngle);              // uglg ? 全局光 : lagl
    effect.Size      = (float)d.GetNumber("blur", 5);
    effect.Noise     = NoiseOf(d);                         // Nose → 0.35
```

**④ 原始数据随时可取**

```csharp
fx.Descriptor.GetNumber("ShdN");        // 抖动：没有投影属性也读得到
layer.GetTaggedBlock("lfx2").Data;      // 原始字节，可与 Photoshop 导出比对
```

## 5. 为什么"只想读效果"也必须从头顺序读？

**因为 PSD 没有索引表。** 文件是一串首尾相接的区段，每一段开头写自己的长度，
后面紧接下一段。要知道第 3 段的起点，必须先读完第 1、2 段——没有"目录"可以直接跳。

真实文件 `PS3.psd`（636,572 字节）的实际布局，用字节偏移量表示：

| 偏移 | 内容 | 长度 |
|---:|---|---:|
| 0 | 文件头 `8BPS` + 尺寸/通道/位深/模式 | 26 |
| 26 | 颜色模式数据长度（=0） | 4 |
| 30 | 图像资源区段长度 | 4 |
| 34 | 图像资源正文（ICC、全局光 1037/1049…） | 27,556 |
| 27,590 | 图层与蒙版区段长度 | 4 |
| 27,594 | 图层信息长度 | 4 |
| 27,598 | 图层记录（每条含通道表 + 额外数据 + tagged block） | 214,952 |
| **28,098** | ↑ 其中 `lfx2` 块的 ASCII 签名出现在这里 | — |
| 376,950 | 合并图像数据（像素） | 259,622 |

要拿到偏移 28,098 的 `lfx2`，必须**依次**算出 27,590 这个值，而它来自 30 这一段的
长度——所以只能顺序读。同理，`lfx2` 在某个图层的"额外数据"里，而该图层的额外数据长度
写在图层记录里，图层记录又排在所有图层记录的第 n 位。

### 但可以"提前停"

解析器读到图层区段结束就 `return`，**从不进入最后的合并图像数据**（本例 259KB 像素
被完全跳过）。所以"从头读"不等于"读完整个文件"：

```
读取量 ≈ 头部 + 图像资源 + 图层结构      （本例约 243KB / 636KB，38%）
真正要解压的像素 = 0 字节
```

### 为什么不做"全文搜索 lfx2"

技术上可以全文搜 ASCII `lfx2`，但它只是块签名，前后都不带长度信息；候选位置还可能
出现在任意二进制里（图案、ICC、文本）。要判断真假仍得回溯解析描述符长度链，
比顺序读更慢更不可靠。顺序读只需一遍，且能同时拿到图层名、可见性、混合模式。

### 自己动手验证（不写一行代码）

1. 用 HxD / 010 Editor 打开 PSD；
2. 搜 ASCII `lfx2`，签名后是 `8BIM` + 4 字节块长度；
3. 数据开头是 `00 00 00 00`（对象效果版本）+ `00 00 00 10`（描述符版本 = 16）；
4. 紧接着是描述符：`00 00 00 00` + 类名 `null` + 条目数 + 每个 key…
5. 搜 `Nose`，它是一个 `#Prc`（百分比）值，后面 8 字节双精度即杂色百分比。

命令行验证本库：

```powershell

```

## 7. 属性对照表

Photoshop 界面 → 描述符键 → 本库属性：

### 投影 / 内阴影
| PS 界面 | 键 | 属性 |
|---|---|---|

| **杂色** | **`Nose`** | **`Noise`**（0~1，无键则 null） |

| 等高线 / 消除锯齿 | `TrnS` / `AntA` | `Contour` / `ContourAntiAliased` |

### 外发光 / 内发光
| PS 界面 | 键 | 属性 |
|---|---|---|
| 杂色 | `Nose` | `Noise` |

## 9. 常见坑

| 现象 | 原因 / 处理 |
|---|---|
| `Noise` 是 `0` 但不是 `null` | 文件里有 `Nose` 键，只是值为 0。两者不可混用 |
| 角度都是 120 | 图层勾了“使用全局光”。读 `doc.GlobalLightAngle`，或看 `uglg` |
| 图层名乱码 | 老文件没有 `luni` 块时才可能；本库优先用 `luni` |
| `layer.Style` 是 null | 该图层没有图层样式（标签里没有 `lfx2`/`lrFX`） |
| 效果存在但 `Enabled=false` | 文件里勾掉的效果也会列出；用 `ActiveEffects` 只取生效的 |
| `Gradient`/`Pattern` 为 null | 该效果用纯色填充，不是渐变/图案 |

## 10. 已知限制

- 不解码像素；不做 ICC 转换（灰度/CMYK 用内置公式，Lab 返回 null）
- 渐变、等高线、图案只映射**文件属性**，不做求值/瓦片解码
- PSB 的大长度分支代码已写但无真实样本验证
- 不是生产级：缺少正式测试项目，`test_documents` 语料尚未接入
